OpenGovDash · Developer API

Pull normalized federal data from OpenGovDash

A public, machine-readable API that returns the same normalized US government data the dashboard shows — you fetch, we do the upstream calls, quirk-handling, and normalization. Two layers: the data API (one agency at a time) and the cross-reference layer (named tables that join several agencies).

Quick start

Base URL:

https://opengov-proxy.psjs.workers.dev

Every record is normalized to a stable shape — title, description, date, link, plus agency-specific rich fields. No key needed for most agencies.

# Recent M2.5+ earthquakes (no key)
curl "https://opengov-proxy.psjs.workers.dev/api/v1/data/usgs/earthquakes?limit=3"

# Federal contract awards mentioning "quantum" (no key)
curl "https://opengov-proxy.psjs.workers.dev/api/v1/data/usaspending/award_search?q=quantum&limit=5"
// Browser / Node fetch
const r = await fetch(
  "https://opengov-proxy.psjs.workers.dev/api/v1/data/fda/drug_recalls?q=insulin&limit=10"
);
const { results } = await r.json();
results.forEach(x => console.log(x.date, x.title));

Authentication

Most agencies need no key. A few (NASA, Congress, FEC, FBI) proxy an api.data.gov service — for those you supply your own free key. We never spend a shared key on your behalf.

# Pass your own api.data.gov key as a query param…
curl "https://opengov-proxy.psjs.workers.dev/api/v1/data/nasa/apod?limit=3&api_key=YOUR_KEY"
# …or as a header
curl -H "X-Api-Key: YOUR_KEY" \
  "https://opengov-proxy.psjs.workers.dev/api/v1/data/congress/bills?limit=5"
Agencies marked key below require your own api.data.gov key. Those marked free need nothing.

Cross-reference layer — /api/db

Named tables that fan out across several agencies and return one unified, normalized result set. Every row keeps the normal shape plus a _source tag ("agency:kind") so you can tell where it came from. This is the layer meant to grow — new joins get added as named tables.

EndpointReturns
GET/api/dbList of tables with their params, sources, and whether a key is needed.
GET/api/db/{table}Run a table. Same params as the data API (q, limit, from, to, format, api_key).

Available tables

TableWhat it joinsSources
drug-safetyOne drug across adverse events, recalls, and clinical trials. (q required)fda/drug_events · fda/drug_recalls · nih/clinical_trials

disaster-responseFEMA declarations + federal spending for the same area/keyword. (q required)fema/disasters · usaspending/award_search

If one source fails, the table still returns the others and lists the failure under partial_errors — a table never fails whole because one upstream hiccuped.

Errors

Errors return { "ok": false, "error": { "type", "message" } } with a matching HTTP status.

StatustypeWhen
400query_requiredSubsection/table needs ?q=.
401api_key_requiredKey-gated source, no key supplied.
404unknown_agency / unknown_subsection / unknown_tableNo such route — check /api/v1/agencies or /api/db.
502upstream_errorThe government upstream errored or timed out.

CORS, caching & limits

  • CORS: Access-Control-Allow-Origin: * — call it directly from any web app. It serves public-domain government data.
  • Caching: keyless responses are edge-cached ~5 min; a cache hit returns X-Cache: HIT. Key-bearing requests are never cached.
  • Attribution: each response carries an attribution string — please keep it with the data.
  • Fair use: this runs on a small shared Worker. Cache on your side and keep limit reasonable. Key-gated agencies count against your api.data.gov quota, not ours.
